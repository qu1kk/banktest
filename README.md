# Отчет по тестированию сервиса F-Bank

## 1. Тест-кейсы (Ручное тестирование)

**TC-1: Успешный перевод (Позитивный сценарий)**
* Вводные данные: Карта `1111222233334444`, сумма `1000`.
* Ожидаемый результат: Комиссия 100 ₽. Появление кнопки "Перевести". Успешное окно после нажатия.
* Фактический результат: Как ожидалось. Тест пройден.

**TC-2: Проверка недостаточности средств**
* Вводные данные: Карта `1111222233334444`, сумма `10000` (при доступных 9999).
* Ожидаемый результат: Появление красной надписи "Недостаточно средств на счете", кнопка "Перевести" отсутствует.
* Фактический результат: Как ожидалось. Тест пройден.

**TC-3: Валидация поля "Номер карты"**
* Вводные данные: Ввод 15 цифр (`111122223333444`) и попытка ввода букв.
* Ожидаемый результат: Буквы не вводятся. При 15 цифрах поле ввода суммы не появляется.
* Фактический результат: Как ожидалось. Тест пройден.

**TC-4: Проверка расчета комиссии для сумм до 100 ₽**
* Вводные данные: Карта `1111222233334444`, сумма `99`.
* Ожидаемый результат: Комиссия 10% округленная вниз = 9 ₽.
* Фактический результат: Комиссия = 0 ₽. **ТЕСТ ПРОВАЛЕН.**

**TC-5: Проверка ввода отрицательной суммы**
* Вводные данные: Карта `1111222233334444`, сумма `-5000`.
* Ожидаемый результат: Ошибка валидации, кнопка "Перевести" не появляется.
* Фактический результат: Комиссия становится отрицательной, кнопка активна, перевод проходит успешно. **ТЕСТ ПРОВАЛЕН.**

## 2. Баг-репорты

### Баг-репорт №1: Некорректный расчет комиссии для сумм меньше 100 рублей
* **Окружение:** Google Chrome, Windows
* **Предусловие:** Открыть страницу `http://localhost:8000/?balance=30000&reserved=20001`, выбрать счет "Рубли".
* **Шаги для воспроизведения:**
  1. Ввести валидный 16-значный номер карты.
  2. В поле "Сумма перевода" ввести значение `99`.
  3. Обратить внимание на текст поля "Комиссия".
* **Ожидаемый результат:** Комиссия составляет 9 ₽ (10% от 99 = 9.9, округление вниз = 9).
* **Фактический результат:** Комиссия составляет 0 ₽.
* **Серьезность:** Высокая.

### Баг-репорт №2: Система позволяет осуществить перевод отрицательной суммы
* **Окружение:** Google Chrome, Windows
* **Предусловие:** Открыть страницу `http://localhost:8000/?balance=30000&reserved=20001`, выбрать счет "Рубли".
* **Шаги для воспроизведения:**
  1. Ввести валидный 16-значный номер карты.
  2. В поле "Сумма перевода" ввести отрицательное значение `-5000`.
* **Ожидаемый результат:** Система выдает ошибку о недопустимом формате суммы, кнопка "Перевести" не отображается.
* **Фактический результат:** Система рассчитывает отрицательную комиссию (-500 ₽), кнопка "Перевести" активна. При нажатии выводится сообщение об успешном переводе.
* **Серьезность:** Критическая.

### 3. Предложения по улучшению качества продукта

На основании проведенного тестирования предлагаю следующие улучшения:

1. **Валидация полей (Frontend):** Строго запретить ввод любых символов, кроме цифр, в поле "Сумма перевода" (блокировать ввод знака минус `-` и других спецсимволов на уровне UI).
2. **Защита на уровне API (Backend):** Реализовать проверку суммы на сервере. Если передается `amount <= 0`, сервер должен отклонять запрос и возвращать ошибку (например, `400 Bad Request`).
3. **Бизнес-логика округления:** Необходимо согласовать с бизнесом минимальную сумму комиссии. Если комиссия при расчете 10% составляет меньше 1 рубля, возможно, стоит внедрить правило "Минимальная комиссия 1 рубль" вместо математического округления до нуля.
4. **Улучшение UX:** При ошибке "Недостаточно средств на счете" не только выводить текстовое сообщение, но и подсвечивать поле ввода суммы красным цветом для лучшей визуальной обратной связи.
